# Fixed Windows profiling task

This helper allows the approved user to start bounded WPR/Nsight recordings
without another UAC prompt after one administrator-approved installation.
It does not resume the game route or qualify a game build.

Any process running as the installing user can start these elevated system-wide
traces and read their results. The traces can include other processes' names,
command lines and stacks. The pipe authenticates the user, not a particular app
or a human approval for each recording. Uninstall the helper when the profiling
campaign ends, using the removal procedure below.

The v0.15 hardening checks for at least **20 GiB free** on the protected output
volume before accepting each capture and again in its worker before recording.
Low space refuses the capture; it never deletes existing evidence. Recordings
require administrator access to delete, and restarting sessions has no lifetime
capture-count limit. This free-space threshold is not a per-capture byte cap:
other applications or a growing capture can still consume the reserve.
An administrator should archive/delete old recordings between campaigns.
Rebuild/reinstall to deploy this check; the original installed binary hashes
in the validation section describe the earlier version.

## Scope

The on-demand `BruteForceProfiler-Collector` task runs the installed native launcher
under the installing user's interactive, elevated token, not SYSTEM. No logon,
timer or recurring trigger is registered. A session lasts at most 30 minutes,
followed by bounded cleanup, and accepts at most four recordings. Restarting the
task starts another bounded session. The Task Scheduler hard limit is 36 minutes.
Keep the user logged on; locking the screen is separate from logging off.

Allowed requests are `cpu3`, `cpu30`, `gpu3`, `gpu30`, `combat30`, `status`,
`stop` and `shutdown`. CPU requests use `wpr -start CPU -filemode`. GPU requests
use non-injecting system-wide WDDM events plus NVIDIA GPU 0 metrics at 1 kHz.
`combat30` records both. Recording names and output locations are generated by
the helper, not supplied by clients. Requests cannot specify commands, paths,
arguments, profiles, applications to inject or processes to terminate.

WPR uses the reserved `BruteForceProfiler` instance name for start, stop,
recovery and cancellation. CPU recording stops before waiting for Nsight report
conversion. Stop is requested after approximately 35 seconds for `combat30`;
the saved ETL can extend through WPR rundown. Use UTC session alignment and crop
the central Nsight 28 seconds for combat analysis. WPR merge
and Nsight conversion each have timeouts. `stop` requests cancellation, salvages
the CPU ETL and may discard an unfinished Nsight report. `shutdown` additionally
ends the broker. Child processes are held in kill-on-close Windows jobs.

## Installation

From an ordinary shell, run `Build.ps1`. It compiles the .NET Framework broker
and separate ordinary client with Windows' C# compiler, plus the native launcher
with MSVC x64 tools. It runs protocol and live transport tests. The build
and SHA-256 receipt go into ignored `games/brute_force_e3/analysis/profiler-helper-build/`.

Run `Install.ps1 -ExpectedSha256 <broker hash> -ExpectedLauncherSha256 <launcher hash>` once in an elevated
Windows PowerShell 5.1 process. Windows may ask for administrator consent here.
Installation refuses an existing destination or task. It verifies the prepared
and installed binary hashes and the installed NVIDIA executable's signature.
Nsight's fixed installed version/path is recorded in protected configuration;
an upgrade requires deliberate administrator maintenance.

Installation writes `C:\ProgramData\BruteForceProfiler` and registers one task.
Administrators and SYSTEM own/control the directory, executable, configuration,
receipts and recordings. The installing user has read/execute permission only.
The native launcher starts the managed broker with a clean environment, excluding
user-controlled CLR/profiler variables before CLR startup. The task's owner is
Administrators; that user receives read/run permission,
not update/delete permission. No password is stored. UAC, HAGS, GPU permission
policies and application defaults are unchanged.

An ACL-restricted local named pipe carries the fixed operation names. Network
clients are rejected. First-instance pipe creation prevents server-name reuse
while the broker runs; the client checks the server PID against a protected
receipt and checks its executable path. Requests have bounded length, encoding
and read/write deadlines. Child environments omit user executable/DLL search
paths and use protected temporary/profile directories. An unexpected default
object owner fails closed rather than creating user-owned privileged files.

`Profile.ps1` uses the separate, non-elevated `Client.exe` built in workspace
`analysis/profiler-helper-build`. Client updates use `BuildClient.ps1` without
administrator rights and cannot expand the installed server's permissions.
Use this client rather than the older embedded `Profiler.exe client` entry point:
it arms its read before sending, avoiding a reply/disconnect race. A 50-exchange
live regression test covers that behavior. If a capture response is lost, check
status before retrying; capture requests are not automatically replayed.

## Use from an ordinary shell

```powershell
.\tools\windows-profiler\Profile.ps1 start
.\tools\windows-profiler\Profile.ps1 status
.\tools\windows-profiler\Profile.ps1 combat30
# Poll status until last_result.status is completed, cancelled or failed.
.\tools\windows-profiler\Profile.ps1 status
.\tools\windows-profiler\Profile.ps1 shutdown
```

`start` only starts the broker; it does not record. It can be called before
leaving the machine idle, or unattended when the approved workflow needs it.
Later capture requests do not invoke RunAs or another elevation prompt.
These commands still depend on host/tool access policies; the Windows task
does not change the coding agent's own permissions.

Results appear under the generated `current_job` / `last_job` GUID in
`C:\ProgramData\BruteForceProfiler\recordings`. The ordinary user can copy files
to ignored workspace `analysis/` for export and hashing. Exports run without
this broker, after all desired recordings finish. Protected originals require
administrator maintenance to delete; check disk space before long campaigns.

For removal, first request `shutdown`, verify no worker/recording remains, then
use an administrator session to unregister this task and remove its exact
installation directory. Do not use Task Scheduler's hard End as routine stop:
abrupt termination can leave the named ETW instance alive. Starting the broker
again performs recovery cancellation of that reserved instance only.

## Validation

`selftest` exercises the operation allowlist, injection-shaped inputs, bounded
framing, invalid encodings and incomplete requests. Installation validation must
also run from a non-elevated token: verify helper/config/directory/task writes
are denied; start/read the broker; record a short CPU and GPU smoke capture;
exercise cancellation and shutdown; verify the named WPR instance is stopped.
This tests installation and unattended dispatch, not game performance.

Run `Validate.ps1` from a non-elevated shell for the short CPU, GPU and cancellation
tests. It writes receipts and copies recordings to an ignored analysis folder,
then shuts down the broker. The game route remains paused unless separately
resumed by the user.

### Installed validation, October 20, 2026

One administrator-approved installation succeeded. Both subsequent validation
sessions started the task from a non-elevated token without RunAs/UAC:

- Helper/config writes and installation-directory creation were denied; file
  owners are Administrators. Updating the task's DACL was denied.
- A raw injection-shaped request was rejected without starting work.
- `cpu3` and `gpu3` completed; the GPU report exported 126,175 metric rows across
  3,605 timestamps. `cpu30` cancellation saved a partial ETL.
- A fresh session completed `combat30` and rejected an overlapping capture.
  Its CPU ETL reports zero lost events/buffers. Stop was requested at 35.05 s;
  the saved ETL spans 56.02 s including rundown, so cropping is required.
- Both brokers shut down, the named/default WPR instances are stopped and the
  task is Ready. Thirty-minute expiry and the four-capture ceiling were reviewed
  in code/settings; those limits were not exhausted in the live smoke test.

The first client validation exposed a buffered reply/disconnect race. That was
fixed entirely in the ordinary client; the installed privileged binaries were
not changed and no second elevation was needed. Fifty live exchanges cover the
fix. Keep using `Profile.ps1`, not the embedded legacy client entry point.
